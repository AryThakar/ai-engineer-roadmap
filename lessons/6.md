# Topic 6: Functions

**The story:** back to the cook. A function is a **recipe card with a name**. Writing the card (`def`) doesn't cook anything; it only puts the card in the drawer. **Calling** the function is the cook following the card. The blanks on the card ("add ___ cups of sugar") are the **parameters**, and what you fill in when you cook is the **arguments**. When the dish is ready, the cook hands it back through the window: that's **`return`**.

Topic 6 builds up like a staircase, so take it step by step:

| Step | Kitchen picture | Interview word |
|---|---|---|
| A card with a name and blanks | recipe card | function, parameters, arguments |
| The dish handed back | the serving window | `return` |
| Blanks with a usual value | "2 spoons, unless told otherwise" | default arguments |
| Any number of extras | a bag for extra ingredients | `*args`, `**kwargs` |
| Where the cook looks for things | own table → outer table → kitchen shelf → city market | scope (LEGB) |
| Cards are things too | put a card in a folder, hand it to someone | first-class functions |
| A card that follows itself | "to peel 5 onions: peel 1, then peel 4" | recursion |
| A card that carries a lunchbox | values packed from the outer kitchen | closure |
| Gift wrapping a card | extra steps before and after | decorator |
| A notebook of finished answers | don't cook the same dish twice | `lru_cache` |

## Part 1: `def`, calling and `return`

### Writing and calling a function

```python
def greet(name):
    """Return a short greeting."""
    return f"Hello, {name}!"

message = greet("Ary")
print(message)
print(greet("Riya"))
```
```output
Hello, Ary!
Hello, Riya!
```

- `def greet(name):` writes the card. `name` is the **parameter** (the blank).
- `greet("Ary")` is the **call**. `"Ary"` is the **argument** (what fills the blank).
- The body is indented, like every block in Python.
- The first string inside is the **docstring** (Topic 1); `greet.__doc__` holds it.

Python reads the `def` line and stores the card, but runs the body only when you call it. So a mistake inside the body only shows up when it's called.

### `return` hands the dish back; `print` only shows it

Remember `reverse_words` failing 0 out of 6? This is why:

```python
def add_return(a, b):
    return a + b

def add_print(a, b):
    print(a + b)

x = add_return(2, 3)
y = add_print(2, 3)
print("x is", x)
print("y is", y)
```
```output
5
x is 5
y is None
```

Look at the order: `5` printed first, because `add_print` printed it while it ran. `x` holds 5, but `y` is `None`, because `add_print` showed the 5 and handed nothing back.

> Hook: print = saying it out loud; return = handing it back.

### No `return` means `None`

A function always gives something back. If it reaches the end without `return`, or has a bare `return`, it gives `None`.

```python
def nothing():
    pass

def bare():
    return

print(nothing(), bare())
```
```output
None None
```

### `return` ends the function at once

Nothing after a `return` runs. This makes "early exit" easy:

```python
def first_negative(nums):
    for n in nums:
        if n < 0:
            return n
    return None

print(first_negative([4, 7, -2, 9, -5]))
print(first_negative([1, 2]))
```
```output
-2
None
```

The loop stops at `-2`; it never even looks at `9` or `-5`.

### Returning several values

`return a, b` returns **one tuple** (the comma makes it, Topic 5). You can unpack it straight away.

```python
def min_max(nums):
    return min(nums), max(nums)

result = min_max([4, 1, 9])
print(result, type(result))
low, high = min_max([4, 1, 9])
print(low, high)
```
```output
(1, 9) <class 'tuple'>
1 9
```

## Part 2: Positional, keyword and default arguments

### Three ways to fill the blanks

```python
def make_tea(sugar, milk="yes", size="small"):
    return f"{size} tea, {sugar} sugar, milk: {milk}"

print(make_tea(2))
print(make_tea(1, "no"))
print(make_tea(0, size="large"))
print(make_tea(size="large", sugar=3))
```
```output
small tea, 2 sugar, milk: yes
small tea, 1 sugar, milk: no
large tea, 0 sugar, milk: yes
large tea, 3 sugar, milk: yes
```

- **Positional:** matched by order. `make_tea(1, "no")` puts 1 in `sugar` and `"no"` in `milk`.
- **Keyword:** matched by name, so the order doesn't matter: `size="large", sugar=3`.
- **Default:** `milk="yes"` is used when you don't pass `milk`. Parameters without a default are required.

### The rules, and the errors when you break them

When you **call**: positional arguments first, then keyword ones.

```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

greet(greeting="Hi", "Ary")
```
```output
SyntaxError: positional argument follows keyword argument
```

When you **define**: parameters with defaults come after the ones without.

```python
def greet(greeting="Hello", name):
    return f"{greeting}, {name}!"
```
```output
SyntaxError: parameter without a default follows parameter with a default
```

The common call mistakes all raise `TypeError` (real Python 3.15 messages):

| Call | Error |
|---|---|
| `greet()` | `greet() missing 1 required positional argument: 'name'` |
| `greet("Ary", "Hi", "extra")` | `greet() takes from 1 to 2 positional arguments but 3 were given` |
| `greet("Ary", name="Riya")` | `greet() got multiple values for argument 'name'` |
| `greet(nme="Ary")` | `greet() got an unexpected keyword argument 'nme'. Did you mean 'name'?` |

The "Did you mean" hint is new in recent Python versions; older ones stop after `'nme'`.

```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

greet("Ary", name="Riya")
```
```output
TypeError: greet() got multiple values for argument 'name'
```

`"Ary"` already filled `name` by position, so `name="Riya"` tries to fill it a second time.

### How arguments are passed (an interview favourite)

"Is Python pass by value or pass by reference?" Neither, exactly. Python passes **the label to the same object** (called **pass by object reference** or **pass by assignment**). Inside the function, the parameter is a new label stuck on the caller's object.

- If the function **changes** that object (like `append`), the caller sees the change, because it's the same box.
- If the function **sticks the label on a new object** (`=`), only the function's label moves. The caller's box is untouched.

```python
def add_item(box):
    box.append("new")      # changes the same list

def replace(box):
    box = ["other"]        # moves only the local label

items = ["old"]
add_item(items)
replace(items)
print(items)

def bump(n):
    n += 1                 # ints can't change, so this makes a new int
    return n

score = 5
print(bump(score), score)
```
```output
['old', 'new']
6 5
```

> Hook: a function gets the same box, not a copy. Changing the box shows outside; re-labelling doesn't.

## Part 3: The mutable default trap

This is one of the most-asked Python trap questions. Read the trace slowly.

```python
def add_item(item, box=[]):
    box.append(item)
    return box

print(add_item("a"))
print(add_item("b"))
print(add_item("c", []))
print(add_item("d"))
```
```output
['a']
['a', 'b']
['c']
['a', 'b', 'd']
```

Most people expect `['b']` on the second line. Here's what really happened:

1. When Python ran the `def` line, it made **one** empty list for the default and stored it with the function.
2. `add_item("a")`: no box given, so it uses the stored list: `['a']`.
3. `add_item("b")`: uses **the same stored list**, which already holds `'a'`: `['a', 'b']`.
4. `add_item("c", [])`: you passed your own new list, so the stored one isn't touched: `['c']`.
5. `add_item("d")`: back to the stored list: `['a', 'b', 'd']`.

**Proof:** the default lives on the function, and you can look at it:

```python
def add_item(item, box=[]):
    box.append(item)
    return box

add_item("a")
add_item("b")
print(add_item.__defaults__)
```
```output
(['a', 'b'],)
```

**Proof that defaults are made once, when `def` runs:**

```python
def make_default():
    print("making the default")
    return []

def f(x=make_default()):
    return x

print("def is done")
f()
f()
```
```output
making the default
def is done
```

"making the default" printed once, before any call, and never again.

**The fix:** use `None` as the default and make a new list inside the function, so each call gets its own.

```python
def add_item(item, box=None):
    if box is None:
        box = []
    box.append(item)
    return box

print(add_item("a"))
print(add_item("b"))
```
```output
['a']
['b']
```

The same trap happens with any default that can change: `{}`, `set()`, a list. Numbers, strings, tuples and `None` are safe defaults, because they can't change.

> Hook: defaults are made once, when def runs. For lists and dicts, default to None.

## Part 4: `*args` and `**kwargs`

### `*args`: any number of positional arguments, packed into a tuple

```python
def total(*nums):
    print(nums)
    return sum(nums)

print(total(1, 2, 3))
print(total())
```
```output
(1, 2, 3)
6
()
0
```

The `*` is what matters; `args` is just the usual name. `*nums` works the same.

### `**kwargs`: any number of keyword arguments, packed into a dict

```python
def profile(name, **details):
    print(name, details)

profile("Ary", role="AI engineer", level="fresher")
profile("Riya")
```
```output
Ary {'role': 'AI engineer', 'level': 'fresher'}
Riya {}
```

### The full order of parameters

```python
def order(a, b=2, *args, c, d=4, **kwargs):
    print(a, b, args, c, d, kwargs)

order(1, 5, 6, 7, c=3, e=9)
```
```output
1 5 (6, 7) 3 4 {'e': 9}
```

Read it left to right: normal ones (`a`, `b`), then `*args` takes the extra positional ones (6, 7). Anything after `*args` can only be given by name (`c`, `d`), and `**kwargs` takes the extra named ones (`e`).

### Unpacking at the call: `*` and `**` work the other way too

In a **def**, `*` and `**` pack. In a **call**, they unpack.

```python
def area(width, height):
    return width * height

size = [3, 4]
print(area(*size))
dims = {"width": 5, "height": 2}
print(area(**dims))
print(*[1, 2, 3], sep="-")
```
```output
12
10
1-2-3
```

`area(*size)` is the same as `area(3, 4)`, and `area(**dims)` is `area(width=5, height=2)`.

### Passing everything straight through

`*args, **kwargs` together accept any call and pass it on unchanged. Decorators (Part 12) depend on this:

```python
def shout_call(func, *args, **kwargs):
    print("calling", func.__name__)
    return func(*args, **kwargs)

print(shout_call(max, 3, 9, 4))
print(shout_call(sorted, [3, 1, 2], reverse=True))
```
```output
calling max
9
calling sorted
[3, 2, 1]
```

> Hook: in def, * and ** pack; in a call, they unpack. *args is a tuple, **kwargs is a dict.

## Part 5: Keyword-only (`*`) and positional-only (`/`)

### A lone `*`: everything after it must be given by name

```python
def connect(host, *, timeout=10):
    return f"{host} (timeout {timeout})"

print(connect("api.example.com", timeout=5))
connect("api.example.com", 5)
```
```output
api.example.com (timeout 5)
TypeError: connect() takes 1 positional argument but 2 were given
```

Why? `connect("api.example.com", 5)` doesn't say what 5 means. Forcing `timeout=5` makes the call readable. Python's own `sorted(items, key=..., reverse=...)` works like this: `key` and `reverse` are keyword-only.

### A `/`: everything before it must be given by position

```python
def power(base, exp, /):
    return base ** exp

print(power(2, 5))
power(base=2, exp=5)
```
```output
32
TypeError: power() got some positional-only arguments passed as keyword arguments: 'base, exp'
```

Why? The author can rename `base` later without breaking anyone's code. Many built-ins are positional-only: `len(obj=[1])` raises `TypeError: len() takes no keyword arguments`.

### Both together

```python
def f(a, b, /, c, *, d):
    return a + b + c + d

print(f(1, 2, 3, d=4))
print(f(1, 2, c=3, d=4))
```
```output
10
10
```

| Where the parameter is | How you must pass it |
|---|---|
| before `/` | by position only |
| between `/` and `*` | either way |
| after `*` (or after `*args`) | by name only |

> Hook: left of / = position only; right of * = name only.

## Part 6: Scope: where Python looks for a name (LEGB)

Every call gets its own fresh worktable (a **local scope**). Names made inside the function live there and disappear when the call ends.

```python
def cook():
    dish = "dal"
    return dish

print(cook())
print(dish)
```
```output
dal
NameError: name 'dish' is not defined
```

### The LEGB rule

When you use a name, Python looks in four places, **inside out**, and stops at the first match:

1. **L**ocal: inside the current function (your own worktable)
2. **E**nclosing: inside any function around it (the outer recipe's table)
3. **G**lobal: the top level of the file (the kitchen's shared shelf)
4. **B**uilt-in: Python's own names like `len`, `print`, `sum` (the city market)

```python
x = "global x"

def outer():
    x = "enclosing x"
    def inner():
        x = "local x"
        print(x)
    inner()
    print(x)

outer()
print(x)
```
```output
local x
enclosing x
global x
```

Three different `x` labels, one per level. Each `print` finds the nearest one. Now take the inner names away, and Python walks outward:

```python
x = "global x"

def outer():
    def inner():
        print(x)       # not local, not enclosing, so global
        print(len)     # not in the file either, so built-in
    inner()

outer()
```
```output
global x
<built-in function len>
```

### Trap: hiding a built-in

A global name is found **before** the built-in one. So naming your own variable `list`, `sum`, `max` or `input` hides Python's:

```python
list = [1, 2, 3]
print(list)
letters = list("abc")
```
```output
[1, 2, 3]
TypeError: 'list' object is not callable
```

Python found your `list` (G) before the built-in `list` (B). Use names like `nums` or `total` instead.

### Trap: assigning a name makes it local for the whole function

Reading a global inside a function is fine:

```python
count = 0

def show():
    print(count)

show()
```
```output
0
```

But **assigning** to a name anywhere in a function makes it local for the **whole** function:

```python
count = 0

def increase():
    count += 1

increase()
```
```output
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value
```

Trace: `count += 1` means `count = count + 1`. Because of the `=`, Python decided, before running anything, that `count` is local in `increase`. Then it tries to read the local `count`, which has no value yet.

It even fails on a line **before** the assignment:

```python
x = 10

def f():
    print(x)
    x = 5

f()
```
```output
UnboundLocalError: cannot access local variable 'x' where it is not associated with a value
```

`print(x)` doesn't fall back to the global, because Python already marked `x` as local (it saw `x = 5` lower down).

### `global`: change the file's name

```python
count = 0

def increase():
    global count
    count += 1

increase()
increase()
print(count)
```
```output
2
```

### `nonlocal`: change the outer function's name

```python
def make_counter():
    count = 0
    def increase():
        nonlocal count
        count += 1
        return count
    return increase

counter = make_counter()
print(counter(), counter(), counter())
```
```output
1 2 3
```

Without `nonlocal`, `count += 1` would make a new local `count` and raise the same `UnboundLocalError`.

**Use `global` rarely.** Any function can change a global, so bugs are hard to trace. Pass values in and return them out instead. `nonlocal` is fine inside closures (Part 11).

> Hook: LEGB = Local, Enclosing, Global, Built-in, inside out. Assigning a name inside a function makes it local everywhere in that function.

## Part 7: Functions are objects (first-class functions)

A recipe card is a thing too. You can give it another label, put it in a folder, hand it to someone, or have one recipe produce another. In Python, functions are objects like numbers and lists (**first-class functions**).

```python
def add(a, b):
    return a + b

def sub(a, b):
    return a - b

plus = add                      # a second label, no ()
print(plus(2, 3), plus.__name__, type(add))

ops = {"+": add, "-": sub}      # stored in a dict
print(ops["-"](10, 4))
```
```output
5 add <class 'function'>
6
```

- `plus = add` copies the label; it doesn't call anything. `add()` with brackets calls it.
- `ops["-"](10, 4)` looks up the function, then calls it. This is called a **dispatch table**: a clean way to replace a long `if/elif` chain.

### Higher-order functions

A **higher-order function** takes a function as an argument, returns one, or both.

```python
def apply_twice(func, value):
    return func(func(value))

def double(n):
    return n * 2

print(apply_twice(double, 3))
print(apply_twice(str.upper, "hi"))
```
```output
12
HI
```

You already used one: `sorted(words, key=len)` passes the function `len` (without brackets) for `sorted` to call on every item.

## Part 8: `lambda`: a small function without a name

`lambda args: expression` makes a tiny function in one line. It returns the expression automatically.

```python
double = lambda x: x * 2
print(double(5))
print((lambda a, b: a + b)(2, 3))

label = lambda n: "even" if n % 2 == 0 else "odd"
print(label(7))
```
```output
10
5
odd
```

### Where lambdas are really used: `key=`

```python
words = ["banana", "kiwi", "apple"]
print(sorted(words, key=lambda w: w[-1]))

students = [("Ary", 82), ("Riya", 91), ("Sam", 77)]
print(max(students, key=lambda s: s[1]))
print(sorted(students, key=lambda s: -s[1]))
```
```output
['banana', 'apple', 'kiwi']
('Riya', 91)
[('Riya', 91), ('Ary', 82), ('Sam', 77)]
```

- The first sorts by the last letter: a, e, i.
- `max(..., key=...)` returns the whole item with the biggest score, not just the score.
- `-s[1]` sorts from high to low.

### What a lambda can't do

A lambda holds **one expression**: no statements like `return`, `=`, `if` blocks or loops.

```python
f = lambda x: return x
```
```output
SyntaxError: invalid syntax
```

If you need more than one line, or you'd give the lambda a name anyway, write a `def`. Style guides say `double = lambda x: x * 2` should be a `def`, because a `def` has a real name in error messages.

> Hook: lambda = one expression, no name, no statements. Best used inside key=.

## Part 9: `map`, `filter` and `reduce`

### `map(func, items)`: apply a function to every item

```python
nums = [1, 2, 3, 4]
squares = map(lambda n: n * n, nums)
print(type(squares))
print(list(squares))
print(list(squares))
```
```output
<class 'map'>
[1, 4, 9, 16]
[]
```

- `map` doesn't build a list. It's **lazy**: it makes each result only when asked (Topic 7). Wrap it in `list()` to see the results.
- The second `list(squares)` is empty. A map can be read only once; after that it's used up.

`map` shines with a ready-made function, like turning text into numbers:

```python
print(list(map(int, ["10", "20", "30"])))
print(list(map(lambda a, b: a + b, [1, 2], [10, 20])))
```
```output
[10, 20, 30]
[11, 22]
```

Online tests often read input this way: `a, b = map(int, input().split())`.

### `filter(func, items)`: keep the items where the function says True

```python
print(list(filter(lambda n: n % 2 == 0, range(10))))
print(list(filter(None, [0, 1, "", "hi", None, [], [5]])))
```
```output
[0, 2, 4, 6, 8]
[1, 'hi', [5]]
```

`filter(None, items)` keeps only the truthy items (Topic 2).

### `reduce(func, items)`: combine everything into one value

`reduce` lives in `functools`. It takes the first two items, combines them, then combines that result with the next item, and so on.

```python
from functools import reduce

print(reduce(lambda total, n: total + n, [1, 2, 3, 4]))
print(reduce(lambda a, b: a if a > b else b, [3, 9, 2]))
print(reduce(lambda total, n: total + n, [], 0))
```
```output
10
9
0
```

Trace of the first one:

| Step | total | n | result |
|---|---|---|---|
| 1 | 1 | 2 | 3 |
| 2 | 3 | 3 | 6 |
| 3 | 6 | 4 | 10 |

The third call passes a starting value (`0`), which is also what you get back for an empty list. Without it, an empty list is an error:

```python
from functools import reduce

reduce(lambda total, n: total + n, [])
```
```output
TypeError: reduce() of empty iterable with no initial value
```

### Which one should you write?

```python
nums = [1, 2, 3, 4, 5]
print([n * n for n in nums if n % 2 == 1])
print(list(map(lambda n: n * n, filter(lambda n: n % 2 == 1, nums))))
print(sum(nums))
```
```output
[1, 9, 25]
[1, 9, 25]
15
```

Same result, but the comprehension is easier to read. Most Python developers prefer **comprehensions** over `map` and `filter` with a lambda, and `sum`, `max`, `min`, `any`, `all` over `reduce`. Use `map` when you already have a named function (`map(int, ...)`).

> Hook: map transforms, filter keeps, reduce combines. map and filter are lazy, so wrap them in list().

## Part 10: Recursion

A recursive function **calls itself** on a smaller version of the same problem. "To peel 5 onions: peel 1, then peel the other 4." Every recursive function needs two parts:

- a **base case**: the smallest problem, answered directly, which stops the calls
- a **recursive case**: the function calls itself on a smaller problem

```python
def factorial(n):
    if n <= 1:                      # base case
        return 1
    return n * factorial(n - 1)     # recursive case

print(factorial(5))
```
```output
120
```

### Watching the calls stack up and come back

Each call waits for the one below it. Python keeps the waiting calls on a pile (the **call stack**).

```python
def factorial(n, depth=0):
    pad = "  " * depth
    print(f"{pad}factorial({n})")
    if n <= 1:
        print(f"{pad}-> 1")
        return 1
    result = n * factorial(n - 1, depth + 1)
    print(f"{pad}-> {result}")
    return result

factorial(4)
```
```output
factorial(4)
  factorial(3)
    factorial(2)
      factorial(1)
      -> 1
    -> 2
  -> 6
-> 24
```

Going down: 4 waits for 3, 3 waits for 2, 2 waits for 1. Coming back up: 1, then 2 × 1 = 2, then 3 × 2 = 6, then 4 × 6 = 24.

### Recursion can repeat a lot of work

```python
calls = 0

def fib(n):
    global calls
    calls += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(20), calls)
```
```output
6765 21891
```

21,891 calls for `fib(20)`, because `fib(18)`, `fib(17)` and so on are worked out again and again. The calls roughly double with each step of `n`: **O(2ⁿ)**. Part 13 fixes this with one line.

### The recursion limit

Python stops a recursion that goes too deep, to protect memory.

```python
import sys
print(sys.getrecursionlimit())

def forever(n):
    return forever(n + 1)       # no base case

forever(0)
```
```output
1000
RecursionError: maximum recursion depth exceeded
```

- The default limit is 1000 calls deep. A missing or wrong base case hits it.
- `sys.setrecursionlimit()` can raise it, but deep recursion is still risky in Python.
- Python doesn't optimise "tail calls" (some languages turn certain recursion into a loop; Python doesn't). For very deep work, write a loop.

Recursion comes back in DSA: trees (22), backtracking (25) and dynamic programming (26).

> Hook: every recursion needs a base case. Python stops at about 1000 calls deep.

## Part 11: Closures

### A function inside a function

```python
def outer():
    message = "hi from outer"
    def inner():
        return message
    return inner()

print(outer())
```
```output
hi from outer
```

`inner` can read `message`, because of the E in LEGB.

### Returning the inner function: a closure

Now return `inner` itself (no brackets), not its result:

```python
def make_multiplier(n):
    def multiply(x):
        return x * n
    return multiply

times3 = make_multiplier(3)
times10 = make_multiplier(10)
print(times3(5), times10(5))
print(times3.__closure__[0].cell_contents)
```
```output
15 50
3
```

`make_multiplier(3)` finished long ago, yet `times3` still knows `n = 3`. The inner function **packed a lunchbox** with the outer values it needs, and carries it around. That's a **closure**: a function plus the enclosing values it remembers. The last line is the proof: the lunchbox holds 3.

A closure needs three things:

1. A function defined inside another function.
2. The inner function uses a name from the outer one.
3. The outer function returns the inner one, so it lives on after the outer call ends.

### Closures keep private state

Each call to `make_counter` makes a new lunchbox, so counters don't share counts:

```python
def make_counter():
    count = 0
    def increase():
        nonlocal count
        count += 1
        return count
    return increase

c1 = make_counter()
c2 = make_counter()
print(c1(), c1(), c1(), c2())
```
```output
1 2 3 1
```

This gives you memory without a global variable or a class. Decorators (next part) are built on closures.

### Trap: closures remember the variable, not the value

```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)

print([f() for f in funcs])
```
```output
[2, 2, 2]
```

Most people expect `[0, 1, 2]`. Trace:

1. Each lambda stores the **name** `i`, not its value at that moment.
2. The loop finishes with `i = 2`.
3. When you finally call the lambdas, each one looks up `i` and finds 2.

This is called **late binding**. The fix is to copy the value into a default argument, which is saved when the lambda is made:

```python
funcs = []
for i in range(3):
    funcs.append(lambda i=i: i)

print([f() for f in funcs])
```
```output
[0, 1, 2]
```

> Hook: a closure carries a lunchbox of outer values. It remembers the variable, not the value, so copy loop values with i=i.

## Part 12: Decorators

### The idea: gift wrapping

A **decorator** is a function that takes a function and returns a new, wrapped version of it. The wrapper adds steps before and after (logging, timing, retrying, checking login) without touching the original recipe.

### Building one by hand, without `@`

```python
def shout(func):
    def wrapper():
        return func().upper() + "!"
    return wrapper

def greet():
    return "hello"

loud_greet = shout(greet)
print(loud_greet())
print(greet())
```
```output
HELLO!
hello
```

`shout` is a higher-order function (takes a function) that returns a closure (`wrapper` remembers `func`). That's all a decorator is.

### The `@` shortcut

```python
def shout(func):
    def wrapper():
        return func().upper() + "!"
    return wrapper

@shout
def greet():
    return "hello"

print(greet())
```
```output
HELLO!
```

`@shout` above `def greet` means exactly `greet = shout(greet)`. The name `greet` now points to the wrapper.

> Hook: @deco on top of def f means f = deco(f).

### A decorator that works for any function

Real decorators use `*args, **kwargs` (Part 4) so they fit any function, and they **return the result**:

```python
def log(func):
    def wrapper(*args, **kwargs):
        print(f"calling {func.__name__} with {args} {kwargs}")
        result = func(*args, **kwargs)
        print(f"{func.__name__} returned {result}")
        return result
    return wrapper

@log
def add(a, b):
    return a + b

total = add(2, b=3)
print(total)
```
```output
calling add with (2,) {'b': 3}
add returned 5
5
```

### Trap: forgetting to return the result

```python
def log(func):
    def wrapper(*args, **kwargs):
        print("calling", func.__name__)
        func(*args, **kwargs)        # the result is thrown away
    return wrapper

@log
def add(a, b):
    return a + b

print(add(2, 3))
```
```output
calling add
None
```

`add` still worked out 5, but the wrapper didn't hand it back, so the caller got `None`. Same lesson as print vs return.

### `functools.wraps`: keep the original name and docstring

```python
import functools

def plain(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

def careful(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@plain
def add(a, b):
    """Add two numbers."""
    return a + b

@careful
def sub(a, b):
    """Subtract b from a."""
    return a - b

print(add.__name__, add.__doc__)
print(sub.__name__, sub.__doc__)
```
```output
wrapper None
sub Subtract b from a.
```

Without `wraps`, the decorated `add` calls itself "wrapper" and loses its docstring. That confuses error messages, logs, `help()` and tools like FastAPI and pytest. Always put `@functools.wraps(func)` on the wrapper.

### A real one: a timer

```python
import functools
import time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.1f} s")
        return result
    return wrapper

@timer
def slow_task():
    time.sleep(0.3)
    return "done"

print(slow_task())
```
```output
slow_task took 0.3 s
done
```

### Decorators with arguments: a retry decorator

Apps that call an LLM API (like Zen-harness talking to its model server) need to try again when the server is busy. `@retry(times=3)` takes a setting, so it needs **one more layer**:

```python
import functools

def retry(times):                       # layer 1: takes the setting
    def decorator(func):                # layer 2: takes the function
        @functools.wraps(func)
        def wrapper(*args, **kwargs):   # layer 3: runs on every call
            for attempt in range(1, times):
                try:
                    return func(*args, **kwargs)
                except ConnectionError as err:
                    print(f"try {attempt} failed: {err}")
            return func(*args, **kwargs)    # last try: let the error out
        return wrapper
    return decorator

calls = 0

@retry(times=3)
def call_model(prompt):
    global calls
    calls += 1
    if calls < 3:
        raise ConnectionError("server busy")
    return f"reply to {prompt!r}"

print(call_model("hi"))
```
```output
try 1 failed: server busy
try 2 failed: server busy
reply to 'hi'
```

`try`/`except` is Topic 8. For now, read it as "try this; if a `ConnectionError` happens, run the `except` part instead of crashing." `raise` creates the error on purpose, here to fake a busy server.

Who calls what:

1. `retry(times=3)` runs first and returns `decorator`, with `times = 3` in its lunchbox.
2. `@` then does `call_model = decorator(call_model)`, which returns `wrapper`.
3. Every `call_model("hi")` now runs `wrapper("hi")`. It tries the real function; tries 1 and 2 fail and are printed; try 3 succeeds and its result is returned.

When every try fails, the last error is let out:

```python
import functools

def retry(times):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times):
                try:
                    return func(*args, **kwargs)
                except ConnectionError as err:
                    print(f"try {attempt} failed: {err}")
            return func(*args, **kwargs)
        return wrapper
    return decorator

@retry(times=3)
def always_down():
    raise ConnectionError("server down")

always_down()
```
```output
try 1 failed: server down
try 2 failed: server down
ConnectionError: server down
```

Real retry code also waits a little longer before each new try (**exponential backoff**). That's Topic 30.

> Hook: a decorator with arguments has three layers: settings → function → each call.

### Stacking decorators

```python
def bold(func):
    def wrapper():
        return "<b>" + func() + "</b>"
    return wrapper

def italic(func):
    def wrapper():
        return "<i>" + func() + "</i>"
    return wrapper

@bold
@italic
def hi():
    return "hi"

print(hi())
```
```output
<b><i>hi</i></b>
```

The decorator **closest to `def` wraps first**: this means `hi = bold(italic(hi))`. Italic is the inner layer, bold the outer.

### Decorators run when `def` runs, not when you call

```python
handlers = {}

def register(func):
    print(f"registering {func.__name__}")
    handlers[func.__name__] = func
    return func

@register
def hello():
    return "hello!"

print("now calling...")
print(handlers["hello"]())
```
```output
registering hello
now calling...
hello!
```

"registering hello" printed before any call. FastAPI works this way (Topic 29): `@app.get("/chat")` registers your function as the handler for that web address.

## Part 13: `functools.partial` and `lru_cache`

### `partial`: a card with some blanks already filled

```python
from functools import partial

def power(base, exp):
    return base ** exp

square = partial(power, exp=2)
cube = partial(power, exp=3)
print(square(5), cube(2))

from_binary = partial(int, base=2)
print(from_binary("1010"))
```
```output
25 8
10
```

`partial(power, exp=2)` makes a new function with `exp` fixed. It's handy when another function wants a function with fewer arguments, like `key=` or `map`.

### `lru_cache`: a notebook of answers already worked out

**Memoisation** means remembering answers so you never compute the same thing twice. `@lru_cache` adds it to any function in one line:

```python
from functools import lru_cache

calls = 0

@lru_cache(maxsize=None)
def fib(n):
    global calls
    calls += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(20), calls)
print(fib.cache_info())
print(fib(100))
```
```output
6765 21
CacheInfo(hits=18, misses=21, maxsize=None, currsize=21)
354224848179261915075
```

- 21 calls instead of 21,891: each `fib(k)` is worked out once, then read from the notebook (18 hits).
- `fib(100)` is instant. Without the cache it would take longer than a lifetime.
- Measured on Python 3.15: `fib(35)` took about 0.7 s without the cache and about 0.00002 s with it.

How it works: the arguments become a dict key, and the answer is the value. So:

- **The arguments must be hashable** (Topic 5). A list fails:

```python
from functools import lru_cache

@lru_cache
def total(nums):
    return sum(nums)

print(total((1, 2, 3)))
total([1, 2, 3])
```
```output
6
TypeError: unhashable type: 'list'
```

- **Only cache pure functions**: same input, same output, no side effects. Don't cache a function that reads the time, a file or a live API.
- `maxsize=128` is the default. When the notebook is full, the **least recently used** answer is thrown out (that's what LRU means). `maxsize=None` never throws anything out.
- `@functools.cache` (Python 3.9+) is a short name for `lru_cache(maxsize=None)`.

This is your first taste of dynamic programming (Topic 26).

> Hook: lru_cache = a notebook of answers. Arguments must be hashable, and the function must be pure.

## 30-second interview answers

- **What is a function, and why use one?** "A named, reusable block of code. You call it with arguments, and it returns a result. Functions remove repetition, make code easier to test, and let you name an idea."
- **print vs return:** "print only shows a value on the screen. return hands the value back to the caller so it can be used. A function without return gives None."
- **`*args` and `**kwargs`:** "`*args` collects extra positional arguments into a tuple, and `**kwargs` collects extra keyword arguments into a dict. In a call, `*` and `**` unpack a list or dict into arguments. Decorators use both to pass any call through."
- **The mutable default trap:** "Default values are made once, when the def runs, not on each call. So a list default is shared by every call and keeps growing. I use None as the default and create the list inside."
- **Pass by value or reference?** "Neither exactly: pass by object reference. The function gets a new name for the same object. Changing a mutable object shows outside; reassigning the name inside doesn't."
- **LEGB:** "Python looks up names in Local, Enclosing, Global, then Built-in scope. Assigning to a name inside a function makes it local, so to change an outer name I need `global` or `nonlocal`, though I avoid globals."
- **lambda:** "A small anonymous function with one expression, mostly used for `key=` in sorted, max or min. Anything longer should be a def."
- **map, filter, reduce:** "map applies a function to every item, filter keeps items that pass a test, reduce combines items into one value. map and filter return lazy iterators. I usually prefer comprehensions and built-ins like sum."
- **Recursion:** "A function that calls itself on a smaller problem until it reaches a base case. Python's default limit is 1000 calls, and it has no tail-call optimisation, so very deep problems are better as loops."
- **Closure:** "An inner function that remembers values from the enclosing function even after that function has returned. It gives private state without globals, and decorators are built on it."
- **Decorator:** "A function that takes a function and returns a wrapped version, adding behaviour like logging, timing, retries or caching. `@deco` means `f = deco(f)`. I use `functools.wraps` to keep the name and docstring. A decorator with arguments has three layers."
- **lru_cache:** "It memoises a function: results are stored by their arguments, so repeated calls are instant. The arguments must be hashable and the function should be pure. It turns recursive Fibonacci from exponential to linear."
- **First-class functions:** "Functions are objects, so I can assign them, store them in a dict, pass them to other functions and return them. That's what makes key=, callbacks and decorators possible."

## Memory hooks

- def writes the card; calling cooks it.
- print = saying it out loud; return = handing it back.
- No return means None.
- A function gets the same box, not a copy.
- Defaults are made once, when def runs. For lists and dicts, default to None.
- In def, * and ** pack; in a call, they unpack. *args is a tuple, **kwargs is a dict.
- Left of / = position only; right of * = name only.
- LEGB = Local, Enclosing, Global, Built-in, inside out.
- Assigning a name inside a function makes it local everywhere in that function.
- global = the file's name; nonlocal = the outer function's name.
- Never name a variable list, sum, max or input.
- lambda = one expression, no name, no statements.
- map transforms, filter keeps, reduce combines; wrap map and filter in list().
- Every recursion needs a base case; Python stops at about 1000 calls deep.
- A closure carries a lunchbox; it remembers the variable, not the value (copy with i=i).
- @deco on top of def f means f = deco(f).
- In a wrapper: always return the result, always use functools.wraps.
- Decorator with arguments = three layers: settings → function → each call.
- Stacked decorators: the one closest to def wraps first.
- lru_cache = a notebook of answers: hashable arguments, pure functions only.
