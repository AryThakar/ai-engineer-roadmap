# Topic 4: Control flow and loops

**The story:** the cook from Topic 1 follows step cards from top to bottom. Two things change that order: **choosing** which card comes next, and **repeating** a card. Every program you will ever write is made of these two moves.

## Part 1: Choosing

### 1. `if` / `elif` / `else`: signposts read from the top

Python checks each condition from the top and runs the **first** branch that is true. All the others are skipped, even if they are also true.

```python
marks = 85
if marks >= 90:
    print("A")
elif marks >= 80:
    print("B")
elif marks >= 70:
    print("C")
else:
    print("F")
```
```output
B
```

85 is also ≥ 70, but that line is never checked. So put the strictest test first. If you write `marks >= 70` first, every mark of 70 or more gets a C.

> Hook: first true wins, and the rest are skipped.

Two separate `if` statements are different from `if`/`elif`: each one is checked on its own.

```python
x = 15
if x > 10:
    print("big")
if x > 5:
    print("medium")
```
```output
big
medium
```

Truthy and falsy values from Topic 2 work here. `if items:` means "if the list isn't empty", and `if x:` is false for 0, `""`, `[]`, `{}` and `None`.

```python
x = 0
if x:
    print("yes")
else:
    print("x is falsy")
items = []
if not items:
    print("empty list")
```
```output
x is falsy
empty list
```

### 2. The ternary (conditional expression), in depth

**Shape:** `A if condition else B`. Read it like English: "A if the condition is true, else B".

**The key idea:** an `if` statement **does things**. A ternary **gives back a value**. That's why it can go anywhere a value can go: an assignment, a `print`, an f-string, a `return`, a comprehension.

```python
age = 20
status = "adult" if age >= 18 else "minor"
print(status)
n = 7
print(f"{n} is {'even' if n % 2 == 0 else 'odd'}")
def abs_val(x):
    return x if x >= 0 else -x
print(abs_val(-5))
```
```output
adult
7 is odd
5
```

**Comprehension trap: an `if` at the end is a different thing.**

```python
print(["even" if n % 2 == 0 else "odd" for n in range(4)])
print([n for n in range(6) if n % 2 == 0])
```
```output
['even', 'odd', 'even', 'odd']
[0, 2, 4]
```

- With an `if … else` **before** the `for`, each item is **transformed**, and you get the same number of items back.
- With an `if` **after** the `for`, items are **filtered**, so some are removed. That `if` can't have an `else`.

An `if` before the `for` is a ternary, so it needs its `else`:

```python
print([n if n > 2 for n in range(5)])
```
```output
SyntaxError: expected 'else' after 'if' expression
```

**Only the chosen side runs:**

```python
x = 0
print(10 / x if x != 0 else 0)
```
```output
0
```

`10 / x` is never calculated, so there's no ZeroDivisionError.

**The rules:**

- The `else` is required, because a value must come out either way.
- Only values can go inside, not statements like `pass` or `return`.
- You can chain them, but more than one level gets hard to read. Switch to if/elif.

```python
x = 5 if True
```
```output
SyntaxError: expected 'else' after 'if' expression
```

```python
x = 1 if True else pass
```
```output
SyntaxError: expected expression after 'else', but statement is given
```

```python
n = 0
print("pos" if n > 0 else "zero" if n == 0 else "neg")
```
```output
zero
```

**The old trick that breaks:** some people write `cond and A or B` instead of a ternary. It fails when A is falsy.

```python
print(True and 0 or 5)
print(0 if True else 5)
```
```output
5
0
```

> Hook: an if statement does; a ternary gives.

**30-second answer:** "It's a one-line if/else that returns a value: `A if cond else B`. Only the chosen side is evaluated, the else is required, and I use it for simple two-way choices, like in a return or an f-string. For anything longer I write a normal if."

### 3. `match` / `case`: Python's switch (3.10+)

A reception desk that compares a request with each case, from the top. Only one case runs.

```python
def reply(cmd):
    match cmd:
        case "start":
            return "starting"
        case "stop" | "quit":
            return "bye"
        case _:
            return "unknown"
print(reply("quit"), reply("dance"))
```
```output
bye unknown
```

- `|` means "or", and `case _:` is the default.
- There's no fall-through like `switch` in C: after one case runs, match is finished.
- If nothing matches and there's no `case _:`, nothing happens. There's no error.

## Part 2: Repeating

### 4. `for`: the conveyor belt

A `for` loop takes each item off any collection, one at a time: a string, a list, a range, a dict, the lines of a file. It doesn't count positions the way C does.

```python
for ch in "abc":
    print(ch)
for key in {"x": 1, "y": 2}:
    print(key)
```
```output
a
b
c
x
y
```

Looping over a dict gives its **keys**. Use `.values()` for the values and `.items()` for (key, value) pairs.

### 5. `range(start, stop, step)`: a belt of numbers

```python
print(list(range(5)))
print(list(range(2, 8, 2)))
print(list(range(10, 0, -3)))
print(list(range(5, 1)))
```
```output
[0, 1, 2, 3, 4]
[2, 4, 6]
[10, 7, 4, 1]
[]
```

- `stop` is never included, just like slicing.
- A negative step counts down.
- `range(5, 1)` is empty, because the default step +1 can't go down. Use `range(5, 1, -1)`.
- range doesn't build a list in memory: it makes each number when it's asked for, so even `range(10**9)` is cheap.
- It only takes whole numbers: `range(2.5)` is a TypeError.

> Hook: range stops before stop.

### 6. `while`, in depth

**Picture it:** a guard at a door who checks a rule **before every round**. If the rule is true, you go in and do the work. If it's false, the loop ends.

**Example 1: counting down**

```python
n = 3
while n > 0:
    print(n)
    n -= 1
print("Go!")
```
```output
3
2
1
Go!
```

| Round | Check `n > 0` | Prints | n after |
|---|---|---|---|
| 1 | 3 > 0 ✅ | 3 | 2 |
| 2 | 2 > 0 ✅ | 2 | 1 |
| 3 | 1 > 0 ✅ | 1 | 0 |
| 4 | 0 > 0 ❌ | the loop ends | |

**Example 2: you don't know the count in advance.** This is where `while` shines. Sum of digits is a classic test question:

```python
num = 1234
total = 0
while num > 0:
    total += num % 10   # take the last digit
    num //= 10          # drop the last digit
print(total)
```
```output
10
```

**Example 3: `while True` + `break`, for when the exit is in the middle** (the "retry until it works" shape):

```python
attempts = ["fail", "fail", "ok"]
i = 0
while True:
    result = attempts[i]
    i += 1
    print("try", i, result)
    if result == "ok":
        break
```
```output
try 1 fail
try 2 fail
try 3 ok
```

Python has **no do-while loop**, so `while True` + `break` is how you get "run at least once". An AI agent loop has this shape too: keep calling the model until it says "done" or you hit a step limit (Topic 51).

**Example 4: `while` with `else`.** It runs when the condition becomes false, as long as there was no `break`:

```python
n = 1
while n < 100:
    n *= 2
else:
    print("stopped at", n)
```
```output
stopped at 128
```

**⚠️ Infinite loop traps:**

- You forget to change the variable: `i = 0` then `while i < 3: print(i)` prints 0 forever.
- The variable jumps past the exit: `n = 5` then `while n != 0: n -= 2` goes 5, 3, 1, -1… and never equals 0. Write `while n > 0` instead.

> Hook: every while needs a door that closes. Something inside must move it towards the end.

**for or while?** Use `for` when you have items to walk through (it stops by itself), and `while` when you're waiting for something to change (retries, reading until a condition).

### 7. `break`, `continue` and `pass`

```python
for n in [1, 2, 3, 4, 5]:
    if n == 2:
        continue
    if n == 4:
        break
    print(n)
```
```output
1
3
```

- `continue` skips the rest of this round (2 is never printed).
- `break` stops the whole loop (4 and 5 never come).
- `pass` does nothing: Python doesn't allow an empty block, so `pass` fills it until you write the real code.
- In nested loops, `break` only leaves the **innermost** loop.

```python
for i in range(2):
    for j in range(3):
        if j == 1:
            break
        print(i, j)
```
```output
0 0
1 0
```

> Hook: break = stop the belt. continue = skip this item. pass = do nothing.

### 8. `else` on a loop

The `else` of a `for` or `while` runs only if the loop finished **without** `break`. That makes it perfect for searches, because the `else` is your "not found" case and you don't need a flag variable.

```python
for n in [3, 7, 9]:
    if n % 2 == 0:
        print("found even", n)
        break
else:
    print("no even number")
```
```output
no even number
```

Even a loop that runs zero times "finished without break", so its `else` runs:

```python
for x in []:
    print(x)
else:
    print("empty")
```
```output
empty
```

> Hook: no break → else runs.

### 9. `enumerate` and `zip`

```python
fruits = ["apple", "mango"]
for i, f in enumerate(fruits, start=1):
    print(i, f)
names = ["Ary", "Riya", "Sam"]
marks = [90, 85]
for name, m in zip(names, marks):
    print(name, m)
print(dict(zip(["a", "b"], [1, 2])))
```
```output
1 apple
2 mango
Ary 90
Riya 85
{'a': 1, 'b': 2}
```

- `enumerate` gives (position, item) pairs, so you never need `range(len(...))`. `start=1` counts from 1.
- `zip` walks the lists side by side. **It stops at the shortest one without warning:** Sam was dropped.
- `dict(zip(keys, values))` is a common one-liner.
- `strict=True` turns the silent drop into an error:

```python
print(list(zip([1, 2, 3], "ab", strict=True)))
```
```output
ValueError: zip() argument 2 is shorter than argument 1
```

## Part 3: Traps, slowly

### Trap A: changing the loop variable

**What really happens:** each round, the `for` loop **puts the next item into `i`**, overwriting whatever you did to it.

```python
for i in range(3):
    print("start of round:", i)
    i = 10
    print("changed to:", i)
```
```output
start of round: 0
changed to: 10
start of round: 1
changed to: 10
start of round: 2
changed to: 10
```

Your `i = 10` lasts only until the next round, when Python puts the next number in again.

In a `while` loop, **you** control the variable, so changing it does change the loop:

```python
i = 0
while i < 3:
    print(i)
    i += 2
```
```output
0
2
```

**The same trap with lists**, which interviewers love. Remember Topic 1: variables are labels. `n = n * 10` moves the label `n` to a new number, and the list never sees it. To change the list, go through its positions:

```python
nums = [1, 2, 3]
for n in nums:
    n = n * 10
print(nums)
for i in range(len(nums)):
    nums[i] = nums[i] * 10
print(nums)
```
```output
[1, 2, 3]
[10, 20, 30]
```

After a loop, the loop variable stays alive with its last value:

```python
for j in range(3):
    pass
print(j)
```
```output
2
```

> Hook: the loop variable is a copy of the label, not the item's seat.

### Trap B: removing items while looping

**What really happens:** a `for` loop over a list keeps a hidden **position counter** (0, 1, 2…). When you remove an item, everything after it **slides left**, but the counter still moves forward, so it **skips** the item that slid in.

```python
nums = [1, 2, 2, 3]
for n in nums:
    print("looking at", n, "| list is", nums)
    if n == 2:
        nums.remove(n)
print(nums)
```
```output
looking at 1 | list is [1, 2, 2, 3]
looking at 2 | list is [1, 2, 2, 3]
looking at 3 | list is [1, 2, 3]
[1, 2, 3]
```

Step by step:

1. Position 0 is `1`, so it stays.
2. Position 1 is `2`. It gets removed, and the list becomes `[1, 2, 3]`. The second 2 slides into position 1.
3. The counter moves on to position 2, which is `3`. **The slid-in 2 was never looked at.**

**Why weren't both 2s removed?** Two separate reasons together:

- `remove()` deletes only the **first** matching value, one item per call.
- Because of the skip, the loop called `remove` only **once**.

```python
nums = [1, 2, 2, 3]
nums.remove(2)
print(nums)
nums = [1, 2, 2, 3]
calls = 0
for n in nums:
    if n == 2:
        nums.remove(n)
        calls += 1
print(nums, "| remove was called", calls, "time")
```
```output
[1, 2, 3]
[1, 2, 3] | remove was called 1 time
```

Removing a value that isn't there is an error:

```python
nums = [1, 3]
nums.remove(2)
```
```output
ValueError: list.remove(x): x not in list
```

**"But sometimes it works?"** Only by luck. The loop always skips the item right after each removal. If that skipped item didn't need removing, the answer happens to be right:

```python
nums = [1, 2, 3, 2]
for n in nums:
    if n == 2:
        nums.remove(n)
print(nums)
```
```output
[1, 3]
```

The same code on other data fails badly. Removing all the even numbers:

```python
nums = [2, 4, 6, 8]
for n in nums:
    print("looking at", n)
    if n % 2 == 0:
        nums.remove(n)
print(nums)
```
```output
looking at 2
looking at 6
[4, 8]
```

The loop never even looked at 4 or 8. A bug that depends on the data is the most dangerous kind: it passes your small test and fails the hidden test cases.

> Hook: if it only works for some inputs, it doesn't work.

**Three correct fixes** (each gives `[1, 3]`):

```python
nums = [1, 2, 2, 3]
print([n for n in nums if n != 2])        # 1. build a new list (best)

nums = [1, 2, 2, 3]
for n in nums[:]:                         # 2. loop over a copy, change the original
    if n == 2:
        nums.remove(n)
print(nums)

nums = [1, 2, 2, 3]
for i in range(len(nums) - 1, -1, -1):    # 3. go backwards by position
    if nums[i] == 2:
        del nums[i]
print(nums)
```
```output
[1, 3]
[1, 3]
[1, 3]
```

Going backwards works because removing from the end doesn't shift the items you haven't checked yet. `while 2 in nums: nums.remove(2)` also works, but it's slow (O(n²)), because every `in` and every `remove` scans the list again.

**With a dict, Python stops you:**

```python
d = {"a": 1, "b": 2}
for k in d:
    del d[k]
```
```output
RuntimeError: dictionary changed size during iteration
```

A list doesn't warn you; it just gives a wrong answer. That's why it's the more dangerous trap.

> Hook: never cut the branch you're sitting on. Loop over a copy, or build a new list.

### Trap C: nested loops multiply

```python
count = 0
for i in range(1000):
    for j in range(1000):
        count += 1
print(count)
```
```output
1000000
```

1000 × 1000 = one million steps. Two nested loops over n items do n × n work, which is O(n²): double the input and it gets 4 times slower.

> Hook: a loop inside a loop = multiply.

## 30-second interview answers

- **break vs continue vs pass:** "break exits the loop, continue jumps to the next round, pass does nothing and just fills a block that can't be empty."
- **Loop else:** "It runs when the loop ends normally, without a break. I use it for searches to handle the not-found case without a flag."
- **for vs while:** "for walks over a collection or range and stops by itself. while repeats until a condition changes, for when I don't know the count, like retries."
- **Ternary:** "`A if cond else B` is a one-line if/else that returns a value. Only the chosen side runs, and the else is required."
- **enumerate and zip:** "enumerate gives index and item together. zip pairs items from several lists and stops at the shortest; strict=True makes it raise instead."
- **Changing a list while looping:** "It skips items, because the list shifts left while the loop's index moves forward. I build a new list with a comprehension, or loop over a copy. A dict raises RuntimeError."
- **Does Python have switch?** "Since 3.10, match/case. Only the first matching case runs, there's no fall-through, and `case _` is the default."
